# Security Policy

## Supported Version

Security fixes are applied to the latest commit on `main` and the latest published release.

## Reporting A Vulnerability

Use the repository's **Security** tab and GitHub's private vulnerability-reporting workflow. Do not open a public issue for suspected vulnerabilities.

Include:

- affected version or commit;
- a minimal reproduction;
- expected impact;
- suggested mitigation, when known; and
- only redacted logs or test data.

Never include Gmail OAuth credentials, access or refresh tokens, environment files, private documents, database exports, encryption keys, or personal email content.

The maintainer will acknowledge a complete report within seven days, assess severity, prepare a private fix, and publish remediation information after affected credentials or releases are secured.

## Disclosure

Coordinate disclosure with the maintainer. Do not publish exploit details before a fix or explicit disclosure agreement is available.
